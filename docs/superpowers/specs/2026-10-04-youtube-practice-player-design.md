# YouTube 練習プレーヤー 設計書

- 日付: 2026-10-04
- ステータス: レビュー待ち

## 1. 目的

iPad で YouTube を見ながら楽器を練習するときに、「区間をくりかえす」「遅くする」を、楽器を持ったまま数タップでできるようにする。

**成功の基準**: 練習中に iPad に手を伸ばしたとき、迷わず数タップで「この区間を遅めでくりかえす」状態にできること。

## 2. 前提と制約

### ユーザーから聞いたこと
- 使う端末は iPad / スマホで、操作はタッチ。PC でも使えるようにする
- 優先順位: 区間ループ → 細かい速度 → 楽器を持ったままの操作性 → 区間の保存
- YouTube Premium に加入済み。広告なしで使いたい
- iPad は縦置きで使う。画面はスマホ / iPad / PC で作り分ける(2026-10-04 追加)

### 試作で確認したこと(2026-10-04、iPad Safari のタブ)
- IFrame Player API の埋め込みでも Premium が効き、広告は出なかった
- `setPlaybackRate(0.85)` のような細かい速度がそのまま反映された
- `getCurrentTime()` を監視して `seekTo()` する方式で A-B ループが動いた。ただし戻るときに少し間がある(埋め込みプレーヤーの再バッファによるもので、ゼロにはできない) → 当初は助走で和らげる設計にしたが、使ってみて不要と判断し 2026-10-04 に削除

### 想定
- 使うのはユーザー本人だけ。公開や配布はしない
- YouTube の規約に従い、広告をプログラムでブロック・スキップする処理は作らない

## 3. スコープ

### 最初のバージョンに入れるもの
- URL を貼って動画を読み込む
- A/B 地点の記録、±0.1 秒の微調整、ループ解除
- 速度 50〜100%(5% 刻み)
- 再生/一時停止、3 秒戻る、A に戻る
- 再生履歴(動画ごとにタイトルと A/B・速度を保存し、選び直すと戻す。2026-10-04 追加)と、起動時の最後の動画の復元
- ホーム画面への追加(manifest)

### 入れないもの
- 100% を超える速度
- オフライン対応(Service Worker)。YouTube 自体がネット接続を必要とするため不要
- iOS ネイティブアプリ化

## 4. 画面

### 共通の部品
- URL 入力欄(文字があるときは右端に「×」を出し、押すと中身を消して入力できる状態にする。2026-10-04 追加)と「読み込む」ボタン
- 動画(16:9)
- シークバー。A〜B のループ区間を色付きで表示し、横にループ解除の「×」を置く
- 操作ボタン:
  - 再生系: 「3 秒戻る」「再生/一時停止」(いちばん大きく)「頭に戻る」(今ループしている範囲の頭へ。2026-10-04 に「A に戻る」から変更)
  - A の操作: 「A」「−0.1」「+0.1」
  - B の操作: 「B」「−0.1」「+0.1」
  - 速度: 「−5%」「現在の速度(例: 85%)」「+5%」
  - 区切り(2026-10-04 追加): 「＋区切り」「−区切り」と区間の選択ボタン「全体」「1」「2」…(区間が多いときは横スクロール)

ボタンの種類と動作はすべての画面で同じ。並べ方だけを画面の幅と向きで切り替える(端末の種類では判定しない。iPad を回転させればレイアウトも切り替わる)。

### レイアウトの切り替え
| 条件 | 想定する画面 | 並べ方 |
|---|---|---|
| 横長(幅 > 高さ)かつ幅 700px 以上 | iPad 横・PC・スマホ横 | 2 カラム。左に URL 欄・動画・シークバー、右に操作ボタン。操作ボタンは「再生系 / A / B / 速度 / 区切り」の 5 段 |
| 上記以外で幅 600px 以上 | iPad 縦 | 1 カラム。上から URL 欄・動画・シークバー・操作ボタン。操作ボタンは「再生系 / A と B を 1 段に並べる / 速度 / 区切り」の 4 段 |
| 上記以外(幅 600px 未満) | スマホ縦 | 1 カラム。並び順は iPad 縦と同じだが、A と B を別の段に分けて 5 段にする |

ボタンは楽器を持ったまま押せるように、指 1 本で確実に当たる大きさ(高さ 56px 以上)にする。スマホでは 64px だと全部が画面に収まらないため 56px を下限とする。

## 5. 動作の仕様

### 区間の設定
- **A**: 押した瞬間の再生位置を A として記録する。既存の B と新しい A の間隔が 0.1 秒未満になる(B が A 以前になる場合を含む)ときは B を消す
- **B**: 押した瞬間の再生位置が A より 0.1 秒以上後ろなら B として記録し、すぐ A へ移動してループを始める。A が未設定、またはそれ以外の位置で押した場合は B を記録せず、「A より後ろで押してください」と短く表示する
- **±0.1 秒**: A/B を 0.1 秒ずつ調整する。A は 0 以上、B は動画の長さ以下にする。A と B の間隔は最低 0.1 秒を保ち、逆転する調整は無視する
- **ループ解除(×)**: A/B を消して通常の再生に戻る

### ループ
- 50ms ごとに再生位置を確認し、A と B が両方設定されていて、位置が B 以上なら A へ `seekTo` する
- ループ中にシークバーで区間の外へ移動しても、ループは止めない(B を過ぎれば戻る)

### その他の操作
- **3 秒戻る**: `max(0, 現在位置 − 3)` へ移動する。ループ中も使える
- **A に戻る**: A が設定されていれば A から再生する。未設定なら何もしない
- **速度**: 50〜100% の範囲で 5% 刻み。押すとすぐ `setPlaybackRate` で反映する。範囲外への変更は無視する

### 区切り(2026-10-04 追加)
- 「＋区切り」で、今の再生位置に区切りを入れる。A だけ設定して B が未設定のときは、B を動画の最後に設定してから区切りを入れる(A → 区切り → … → 最後に B、の順で使えるように。あとで B を押すと B はその位置に移り、B より後ろの区切りは消える)。A が未設定なら押せない。A・B・ほかの区切りから 0.1 秒以上離れた A-B の内側でだけ有効。外で押したら「A と B の間で押してください」と表示する。区切りは 9 個まで(超えたら「区切りは 9 個までです」)
- 「−区切り」で、今の再生位置にいちばん近い区切りを 1 つ消す
- 区切りで分けた区間を「1」「2」…で選ぶと、その区間の頭から再生し、区間の終わりを過ぎたら頭に戻る。「全体」で A-B 全体のループに戻る。選んでいるボタンを強調する
- 再生バーには区切りの位置を線で、選んでいる区間を濃い色で表示する
- A/B を動かして区切りが A-B の外に出たら(または 0.1 秒未満まで近づいたら)、その区切りを消す。ループ解除(×)で区切りも消す
- 区切りを足したり消したりしても、選んでいた区間と同じ位置から始まる区間があれば選び続ける。なければ「全体」に戻す
- 区切りは動画ごとに履歴へ保存する。どの区間を選んでいたかは保存しない

### 再生バーのスライド(2026-10-04 追加)
- 再生バーに指を置いてスライドしている間は、位置の線と時刻の表示だけが指に合わせて動き、指を離した位置へ移動する。タップでも移動できる
- スライド中に画面がスクロールしないよう、再生バーでは `touch-action: none` にする

### 再生履歴と状態の復元(2026-10-04 追加)
- 履歴は `localStorage` に、新しい順に最大 30 件保存する。1 件ごとに 動画 ID、タイトル、A、B、速度、区切り、最後に開いた日時 を持つ
- 動画を開くと(URL からでも履歴からでも)その動画を履歴の先頭に入れる。履歴にある動画なら先頭へ移し、保存してある A/B・速度を戻す。初めての動画は A/B なし・速度 100% で始める
- 上限を超えたら古いものから消す
- タイトルは読み込み後にプレーヤーから取得する。取れるまでは動画 ID を表示する
- A/B・速度が変わるたびに、今の動画の履歴の項目に上書き保存する
- URL 欄の横の「履歴」ボタンで、画面全体に一覧を開く。各行はタイトル、最後に開いた日時、保存してある設定(例: `A 1:02.3〜B 1:15.0 / 85%`)を表示し、タップでその動画を開き、「×」でその 1 件を消す
- 起動時は履歴の先頭の動画を、その設定ごと読み込む。自動再生はしない
- 以前の形式(最後の状態 1 件)が保存されていて履歴がないときは、それを履歴の 1 件目として引き継ぐ
- 保存・読み込みに失敗した場合や、中身が壊れている場合は、何も表示せずに使える項目だけで起動する(全部だめなら空の履歴)

## 6. 構成

ビルドの仕組みやフレームワークは使わず、HTML・CSS・JavaScript(ES Modules)だけで作る。

| ファイル | 役割 | 依存先 |
|---|---|---|
| `index.html` | 画面の骨組み。IFrame API の読み込み | — |
| `style.css` | 3 種類のレイアウト(メディアクエリで切り替え)、ボタンの大きさ | — |
| `loop.js` | A/B・速度の計算だけを担当する純粋な関数群(ループで戻るかの判定、A/B 設定時の検証、±0.1 の制限、速度の範囲制限、URL からの動画 ID 抽出) | なし |
| `player.js` | `YT.Player` を薄く包む(読み込み、再生/停止、現在位置、移動、速度設定、エラー通知) | YouTube IFrame API |
| `history.js` | 履歴の追加・先頭への移動・上限・削除・壊れたデータの扱い(純粋な関数) | `loop.js` |
| `sections.js` | 区切りの追加・削除・区間の一覧・A/B を動かしたときの整理(純粋な関数) | `loop.js` |
| `storage.js` | 履歴の保存と読み込み、以前の形式からの引き継ぎ。例外はすべて内部で処理する | `history.js` / `localStorage` |
| `app.js` | ボタンのイベント、50ms ごとの監視、画面と履歴一覧の更新。上をつなぐ | `loop.js` / `history.js` / `player.js` / `storage.js` |
| `manifest.webmanifest` + アイコン | ホーム画面に追加したときの名前・アイコン・全画面表示 | — |

`loop.js` は YouTube にもブラウザにも依存させない。ロジックをここに集めて、自動テストの対象にする。

## 7. エラー時の扱い

| 状況 | 表示 |
|---|---|
| URL から動画 ID を読み取れない | 「URL を確認してください」 |
| 埋め込みが禁止された動画(エラー 101 / 150) | 「この動画は埋め込み再生が許可されていません(YouTube アプリで見てください)」 |
| 動画が存在しない(エラー 100) | 「動画が見つかりません」 |
| その他のプレーヤーエラー | 「再生できませんでした(エラー番号)」 |
| 状態の保存・復元の失敗 | 表示しない。初期状態で起動する |

メッセージは画面上部に数秒表示して消える。

## 8. リスク: ホーム画面から起動したときの Premium

iOS では、ホーム画面から起動した Web アプリは Safari とは別の Cookie を持つ。そのため、ホーム画面から起動したときに Premium のログイン状態が引き継がれず、広告が出る可能性がある。

**対応**: 実装の最初の手順として、最小限のページを GitHub Pages に置き、ホーム画面から起動して広告の有無を確認する。広告が出る場合は、Safari のブックマークから開く使い方にする(機能は同じ)。

## 9. 確認方法

- **自動テスト**: `loop.js` を Node.js の標準テストランナー(`node --test`)でテストする。追加の依存パッケージは使わない。対象は、ループで戻るかの判定、A/B 設定時の検証、±0.1 秒の制限、速度の範囲、URL の解析(`watch?v=`、`youtu.be/`、`shorts/`、ID のみ)
- **実機での手動確認**: チェックリストを用意し、ユーザーに確認してもらう(ループ・速度・復元・エラー表示・ホーム画面起動時の広告、iPad 縦横・スマホ縦横・PC のレイアウト)

## 10. 公開

- GitHub に `youtube-player` リポジトリ(公開)を作り、`main` ブランチのルートを GitHub Pages で配信する
- URL: `https://<ユーザー名>.github.io/youtube-player/`
- パスワードなどの秘密情報は含まない
- GitHub Pages はファイルを 10 分間ブラウザに保存させるため、更新直後に新しい HTML と古い JS が混ざることがある(2026-10-04 に実際に発生: 助走の段が消えたのに 1 秒手前から再生された)。これを防ぐため、`index.html` から読み込む JS / CSS には中身から計算した版番号(`?v=…`)を付ける。モジュールは import map で版番号付きの URL に振り替える
- JS / CSS を変えたら `npm run stamp` で版番号を書き込む。版番号が中身と合っていないと `npm test` が失敗するので、書き込み忘れのまま公開しない
