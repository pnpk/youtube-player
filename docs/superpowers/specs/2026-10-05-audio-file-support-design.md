# 音声ファイル(MP3 / WAV)対応 設計書

- 日付: 2026-10-05
- ステータス: レビュー待ち
- 元の設計書: `docs/superpowers/specs/2026-10-04-youtube-practice-player-design.md`(YouTube 版。ここに書いていないことは元の設計書のとおり)

## 1. 目的

YouTube の動画と同じ使い勝手(A-B ループ・区切り・速度・ループバー・キーボード操作・履歴)で、手持ちの音声ファイル(MP3 / WAV など)を練習に使えるようにする。音声ファイルでは曲全体の波形を表示し、波形を見ながら再生位置や A / B を決められるようにする。

**成功の基準**: iPad で音声ファイルを開き、波形を見ながら A-B を決めてスロー再生でくりかえせること。次に開いたとき、履歴から選ぶだけで同じ状態に戻れること。

## 2. ユーザーと決めたこと

- ファイルの中身もブラウザに保存し、履歴からそのまま開けるようにする(選択肢 A)
- 最初のバージョンに入れるのは **MP3 / WAV の再生と波形の表示**。継ぎ目のないループ、A-B 範囲の WAV 書き出し、動画ファイル(MP4 など)は入れない
- 再生はブラウザ標準の音声再生(audio 要素)で行い、波形は別に計算する(方式 ①)。速度を落としても音程が変わらないことを優先する
- 画面は A 案: 動画の枠のところに曲全体の大きな波形を表示する
- 履歴からファイルを削除したときは、保存した中身と波形も一緒に消す

## 3. スコープ

### 入れるもの
- ♪ ボタン(と PC でのドラッグ & ドロップ)で音声ファイルを開く
- 音声ファイルの再生。A-B ループ・区切り・速度(50〜100%、音程を保つ)・ループバー・キーボード操作・ヘルプは YouTube と同じように使える
- 曲全体の大きな波形(動画の枠のところ)と、ループバーの背景の拡大波形
- ファイルの中身と波形のブラウザ内への保存(合計 1GB まで)
- 履歴に YouTube と音声ファイルを一緒に並べる

### 入れないもの
- 継ぎ目のないループ(Web Audio での直接再生)
- A-B 範囲の書き出し、自分の演奏の録音
- 動画ファイル(MP4 など)
- ID3 タグ(曲名・アーティスト・ジャケット)の読み取り。表示名はファイル名(拡張子なし)
- YouTube の音声の波形(規約と技術の両面で不可)

## 4. 画面

### ファイルの開き方
- URL 欄の右(履歴・ヘルプのアイコンの並び)に ♪ ボタンを置く。押すとファイル選択を開く(`accept="audio/*,.mp3,.wav,.m4a,.aac"`)。iPad では「ファイル」アプリから選べる
- PC ではページにファイルをドラッグ & ドロップしても開ける。ドラッグ中はページ全体に「ここにドロップして開く」の表示を出す
- 音声ファイルを開いたら URL 欄は空にする

### 大きな波形(音声ファイルのとき、動画の枠の代わり)
- 動画と同じ枠(16:9)に、曲全体の波形をカード状に表示する。YouTube の枠は隠して止める
- 枠の下部に、ファイル名(拡張子なし)と長さを表示する
- 波形は縦棒の並び。A-B の範囲の棒はアクセント色、範囲外は薄い灰色。区間を選んでいるときは、その区間の棒を区間の色にする。A-B の範囲には薄い背景色を敷く
- 再生位置は縦線で表示する
- 波形の上をタップ、または指を置いたままスライドすると、その位置へ移動する(スライド中は縦線と時刻だけが指についてきて、離した位置へ移動する。上の再生バーと同じ動き)
- 波形の計算中は「波形を作成中…」、計算に失敗したときは波形を出さずに「波形を表示できません」と表示し、再生はそのまま使える

### ループバー
- 音声ファイルのときは、ループバーの背景に表示範囲の波形を拡大して描く。その上に、これまでどおり区間の色の帯(半透明)・目盛り・A / B のつまみ・再生位置を重ねる
- 操作(つまみのドラッグ、スライドでの移動、移動先を A〜B に収める)は変えない

### その他
- 再生バー・再生ボタン・ループ・速度・区切りのカードは YouTube のときと同じ
- 履歴の一覧では、音声ファイルの行のタイトルの前に ♪ を付ける

## 5. 動作の仕様

### ファイルを開く
1. ファイルの識別子を作る: `f:<大きさ>:<更新日時>:<ファイル名>`(`fileId`)。同じファイルを選び直せば同じ識別子になる
2. 音声を再生プレーヤーに読み込む(自動再生しない)。読み込めなければ「このファイルは再生できません」と表示して終わる(保存も履歴への追加もしない)
3. 履歴の先頭に入れる。履歴にあるファイルなら、A / B・区切り・速度を戻す(速度がなければ 100%)。30 件を超えて押し出された記録が音声ファイルなら、その保存データを消す
4. ファイルをブラウザのデータベースに保存する(同じ識別子があれば上書き)。最後に開いた日時を記録する
5. 保存後、合計が 1GB を超えていれば、最後に開いた日時が古いファイルから中身と波形を消す(今開いたファイルは消さない)。このとき履歴の記録は残す
6. 波形: 保存済みの波形があればそれを使う。なければ音声を解析して計算し、保存する(計算中も再生や操作はできる)

### 再生
- ブラウザ標準の audio 要素で再生する。`preservesPitch = true`(古い Safari 向けに `webkitPreservesPitch` も)で、速度を落としても音程を保つ
- A-B ループ・区切りの判定は YouTube と同じ(50ms ごとに位置を確認し、B を過ぎたら A へ)。終端で ENDED になったときの扱いも同じ
- YouTube の動画を開いたら音声ファイルの再生は止め、波形を隠して YouTube の枠を表示する。逆も同じ

### 起動したとき
- 履歴の先頭が音声ファイルなら、保存しておいた中身から自動で開く(自動再生しない)
- 中身が消えていたら(容量の上限、または Safari が保存データを消した場合)、「ファイルが見つかりません。♪ からもう一度選んでください」と表示する。設定は残っているので、同じファイルを選び直せば元に戻る
- 起動時に、保存データのうち履歴に対応する記録がないファイル(と波形)を消す

### 保存データの削除
- 履歴で「削除」を押したとき、それが音声ファイルなら、保存した中身と波形も消す
- 履歴が 30 件を超えて押し出された記録が音声ファイルなら、その中身と波形も消す
- 容量の上限(1GB)で消すときは中身と波形だけを消し、履歴の記録は残す

### 履歴の形式
- 1 件の形を `{ kind: 'youtube' | 'file', id, title, a, b, rate, markers, openedAt }` にする。`id` は YouTube なら動画 ID、ファイルなら `fileId`
- 今ある履歴(`videoId` を持つ形)は、読み込むときに `kind: 'youtube'`、`id: videoId` として引き継ぐ。保存は新しい形で行う(保存先のキーは変えない)
- ファイルの `id` は `f:` で始まる 300 文字以内の文字列だけを有効とする。タイトルは拡張子を除いたファイル名

## 6. 構成

| ファイル | 役割 | 新規 / 変更 |
|---|---|---|
| `audio-player.js` | 音声ファイルの再生。YouTube 用の `player.js` と同じ操作の形(`load` / `play` / `pause` / `isPlaying` / `time` / `duration` / `seek` / `setRate` / `title`、状態の通知)を持つ | 新規 |
| `waveform.js` | `computePeaks`(音声データ → 波形の山の高さ。純粋な関数)、音声の解析(`AudioContext.decodeAudioData`)、canvas への描画 | 新規 |
| `media-store.js` | IndexedDB への保存と読み出し(ファイルの中身、波形)。`pickEvictions`(1GB を超えたときに消すもの。純粋な関数)、`findOrphans`(履歴にない保存データ。純粋な関数) | 新規 |
| `history.js` | `kind` / `id` 形式への変更、以前の形式からの引き継ぎ、押し出された記録を返す | 変更 |
| `app.js` | 今のプレーヤー(YouTube / ファイル)の切り替え、ファイルを開く流れ、大きな波形とループバーの波形の描画、保存データの削除 | 変更 |
| `index.html` / `style.css` | ♪ ボタン、ファイル選択、ドロップの表示、大きな波形の枠 | 変更 |
| `tools/stamp-version.mjs` | 版番号の対象に新しいファイルを足す | 変更 |

### 保存先(IndexedDB)
- データベース名 `yt-practice-player`、版 1
- `files`: `{ id, name, type, size, blob, lastOpenedAt }`(キーは `id`)
- `peaks`: `{ id, buckets, peaks }`(キーは `id`。`peaks` は 0〜1 の数値の配列)

### 波形の計算(`computePeaks`)
- 入力: チャンネルごとの音声データ(`Float32Array` の配列)と分割数(既定 2000)
- 出力: 長さ = 分割数の配列。各要素は、その区間の全チャンネルの振幅の最大値(絶対値)を、曲全体の最大値で割った 0〜1 の値。全体が無音なら 0 のまま

## 7. エラー時の扱い

| 状況 | 表示と動き |
|---|---|
| 開けない形式・壊れたファイル | 「このファイルは再生できません」。履歴には入れない |
| 保存できない(容量不足、プライベートブラウズなど) | 再生だけ行い、「ブラウザに保存できなかったため、次回は選び直しが必要です」と表示する |
| 波形の計算に失敗 | 波形の枠に「波形を表示できません」。再生はそのまま |
| 起動時に中身が見つからない | 「ファイルが見つかりません。♪ からもう一度選んでください」 |
| IndexedDB 自体が使えない | 保存できない場合と同じ扱い。履歴(localStorage)の記録は残る |
| 開けないファイルを選んだとき、別のファイルを再生中だった | それまでのファイル(と再生位置)に戻し、練習を続けられるようにする |
| 200MB を超えるファイル | 波形は作らず「波形を表示できません」。再生はできる(iPad で解析中にメモリが足りなくなるのを避ける) |
| 波形の解析中にタブが落ちた | 解析中のファイルを目印として残しておき、次に起動したときは同じファイルを解析し直さない(「波形を表示できません」) |

- 波形の解析は 8kHz・1 チャンネルで行う(`OfflineAudioContext`)。形を見るには十分で、長い曲でもメモリを約 1/6 に抑えられる
- 保存の成否は、データベースの書き込みが確定した時点(トランザクションの完了)で判断する。容量不足は確定の直前に失敗として届くため
- 起動時に保存データが見つからなかったときは、どのファイルも開いていない状態に戻す(ボタンの操作で履歴の設定を上書きしないため)。履歴の記録は残す
- 別のものを開くたびに前の波形を消す(計算中・計算失敗のときに、前のファイルの波形を出さない)

## 8. 確認方法

### 自動テスト(`node --test`、テストを先に書く)
- `computePeaks`: 分割、複数チャンネルの最大値、0〜1 への正規化、無音、分割数より短い音声
- `fileId`: 同じファイル情報から同じ識別子、違えば違う識別子
- `pickEvictions`: 古い順に消す、今開いたファイルは消さない、上限以内なら何も消さない
- `findOrphans`: 履歴にない保存データだけを返す
- 履歴: `kind` / `id` 形式、以前の形式(`videoId`)からの引き継ぎ、不正なファイル ID の除外、30 件を超えて押し出された記録を返す
- 版番号: 新しいファイルが版番号の対象に入っている(既存のテストで確認される)

### ブラウザでの確認(Mac の Chrome)
- 確認用の WAV(拍ごとに音量が変わる数十秒の音)を Node のスクリプトで作る
- 開く → 波形 → A-B ループ・区切り・速度 → 波形とループバーのスライド → 再読み込みで戻る → 履歴から YouTube と行き来 → 履歴から削除で保存データが消える、を確認する
- スマホ縦・iPad 縦・横長の画面で、はみ出しがないことを確認する

### 実機での確認
- `docs/manual-check.md` に「音声ファイル」の節を追加し、iPad で確認してもらう(「ファイル」アプリから開ける、遅くしても音程が変わらない、次回履歴から開ける など)
